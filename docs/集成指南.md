# 集成指南

本文面向宿主系统和管理端开发者。组件不接管认证、业务授权、Controller URL 或前端；它提供可组合的强类型契约和 Spring Bean。

## 1. 安装顺序

1. Boot 2.1 使用 `spring2-legacy-starter`，Boot 2.7 使用 `spring2-starter`，Boot 3 使用 `spring3-starter`，不要同时引入。
2. 用宿主迁移工具执行 `mybatis/src/main/resources/db/monitoring-schema.sql`。
3. 确认应用存在可用的 `SqlSessionFactory`。缺失时 Starter 必须启动失败。
4. 设置稳定 `system-id`，先使用 `OBSERVE`。
5. 注册可信身份、资源授权、代理解析和通知适配。
6. 验证事件、告警、控制、管理授权和审计后再评估 `ENFORCE`。

组件不会自动建表，也没有生产内存回退。H2 仅用于测试。

## 2. Action 和 Fact

### 内置 Action

内置 Action 的事实责任如下。表中的“组件已实现”表示组件会完成目录注册、来源校验、类型校验、编码和持久化；“宿主必须提供”表示集成代码必须在真实业务决策点提交，组件无法从通用 HTTP 请求中可靠推断。

| Action | 事件编码 | 内置规则依赖的事实 | 组件已实现 | 宿主必须提供 |
| --- | --- | --- | --- | --- |
| LoginFailure | auth:login-failure | 无强制 Fact；AUTH-01/02/03 使用失败结果、账号状态/原因、用户和来源 IP | Action 注册、失败结果分类、事件组装、规则评估和告警/控制编排 | 在认证结果确定后显式提交失败原因、尝试账号归并信息和可信身份/来源 IP |
| Query | data:query | AUTHZ-02 需要 sequential_access 和 resource_id；DATA-01/02 需要查询事件和资源 ID | 查询 Action、Fact 定义、窗口/去重聚合和告警控制 | 在查询业务层标记是否顺序遍历，并提交服务端资源 ID；不要用客户端分页参数代替资源事实 |
| SensitiveView | resource:view-sensitive | DATA-03 需要 sensitive=true、work_hours=false 和 data_count；DATA-02 可使用资源 ID | 敏感查看 Action 和 Fact 校验 | 由服务端资源分类、工作时段策略和实际数据量生成事实 |
| ReportExport | report:export | EXPT-01/02 需要 resource_id、data_count；可选 sensitivity、baseline_ratio | 导出契约、FAIL_CLOSED 校验、告警、审批/拒绝和通知流程 | 在导出前提交预检事实；文件生成后再提交最终实际行数/结果，不能直接信任请求体数量 |
| SessionConcurrent | session:concurrent | SESS-01 需要 data_count >= 3 和 different_networks=true | 会话并发规则和 MFA 控制编排 | 从会话系统计算并发会话数和来源网络差异 |
| AccessDenied | authz:access-denied | AUTHZ-01 使用拒绝事件次数；AUTHZ-02 也接收资源范围拒绝 | 资源授权拒绝 Action 和拒绝后的规则处理 | 在授权实际拒绝的位置提交目标资源和拒绝原因；不能把组件作为授权放行入口 |
| AccessAllowed | authz:access-allowed | 当前无默认规则强制依赖 | 事件记录和规则目录 | 仅在需要分析“允许但异常”时提交，不要为每个无风险请求无条件埋点 |
| PrivilegeChange | privilege:change | PRIV-01/02 强制 target_user_id、privilege_increase；可选 high_privilege | 提权 Action、FAIL_CLOSED 校验和 MFA/审批/拒绝控制编排 | 在权限变更前后由服务端确定目标用户、是否提权及权限等级；拒绝应先于权限写入 |
| SecurityChange | security:configuration-change | SECU-01 根据事件类型识别规则、审计和安全开关变更 | RECORD 留证规则和管理审计能力 | 在安全配置真正变更的位置提交变更结果；RECORD 不会替宿主阻止变更 |
| FrontendSignal | frontend:signal | 当前不绑定内置规则；resource_id 只能来自 CLIENT_SUPPLEMENTAL | Schema 校验入口和补充信号记录 | 先完成认证、限流和服务端上下文补充；不能用浏览器字段覆盖身份、IP、授权或触发控制 |

#### 内置 Fact 目录

| Fact | 存储键/类型 | 允许的主要来源 | 集成者何时提供 |
| --- | --- | --- | --- |
| ResourceId | resource_id / String | TRUSTED_REQUEST、HOST_PROVIDER，部分场景允许客户端补充 | 已解析目标资源后提供；跨租户授权、查询、导出必须使用服务端资源 ID |
| DataCount | data_count / Long | METHOD_PARAMETER、HOST_PROVIDER | 实际查询/导出/批处理规模已知时提供；值必须非负 |
| Sensitivity | sensitivity / String | TRUSTED_REQUEST、HOST_PROVIDER | 由服务端资源目录或业务策略提供，例如 low、medium、high |
| DifferentNetworks | different_networks / true/false | METHOD_PARAMETER、HOST_PROVIDER | 会话系统确认同一主体是否来自不同网络时提供 |
| SequentialAccess | sequential_access / true/false | METHOD_PARAMETER、HOST_PROVIDER | 查询/读取路径确认存在连续资源遍历特征时提供 |
| Sensitive | sensitive / true/false | METHOD_PARAMETER、HOST_PROVIDER | 当前访问对象被业务分类为敏感对象时提供 |
| WorkHours | work_hours / true/false | METHOD_PARAMETER、HOST_PROVIDER | 按宿主时区和工作时段策略计算后提供 |
| PrivilegeIncrease | privilege_increase / true/false | METHOD_PARAMETER、HOST_PROVIDER | 权限变更前比较新旧权限后提供 |
| HighPrivilege | high_privilege / true/false | METHOD_PARAMETER、HOST_PROVIDER | 目标角色/权限属于高危集合时提供 |
| TargetUserId | target_user_id / String | METHOD_PARAMETER、HOST_PROVIDER | 权限或账号操作的目标用户由服务端解析后提供 |
| BaselineRatio | baseline_ratio / String | METHOD_PARAMETER、HOST_PROVIDER | 宿主有稳定历史基线并完成计算时提供；必须是有限非负数 |

Fact 的定义、最大长度、布尔值规范、数值校验、持久化 codec 和 monitoring_security_event_fact 写入由组件完成。集成者不能用 toString() 代替 Fact 编码，也不能把未知 Fact 或同一 Action/Fact 的多个生产者同时注册。

### 内置监听与集成责任清单

Starter 自动提供并维护：请求 ID、方法、路径、可信来源 IP 的请求上下文适配；内置 Action/Fact/Rule 目录；事件组装和字段清洗；MyBatis 事件、告警、控制、通知状态及管理审计；规则窗口计算；告警去重；控制命令幂等键；通知租约和有限重试；MonitorAction 切面和 ActionFact 受限路径提取。

集成者必须决定并实现：认证后的 IdentityContext；资源级授权；真实业务 Action 的触发位置；上述表格中的服务端 Fact；会话、限流、MFA、审批和拒绝等宿主控制副作用；外部通知渠道；管理端操作者和系统范围授权；数据库迁移和备份权限。

仅有请求上下文不会自动生成业务事件。仅加 MonitorAction 也不会自动得到实际行数、敏感级别、组织范围或事务结果。对登录、导出、权限变更、异步任务和消息消费，应优先在 Service 的程序化入口提交可信事实。
`BuiltInActions` 提供登录失败、查询、敏感查看、报表导出、权限变更、安全配置变更、授权允许/拒绝和前端补充信号等类型。每个类型均对应一个冻结的 `ActionDefinition`。

### 自定义监听快速规则

自定义 Action 必须是具体 `final` 类。需要共享语义时实现公开 `ActionContract`，不要通过字符串前缀或继承猜测关系。

```java
public interface BulkRead extends ActionContract { }

public final class InvoiceExport implements ActionType, BulkRead {
    private InvoiceExport() { }
}
```

在 `ActionCatalog` 中注册编码、事件类型、资源类型、Fact、规则和失败策略，并在创建运行时前 `freeze()`。重复类型、重复编码、抽象 Action 和冻结后变更都会失败。

### Fact Provider 的归属

`ActionFactProvider` 只负责从只读 `ActionExecution` 产生 Fact；`FactBinding` 才拥有适用范围：

自定义 Fact 还必须提供唯一 `FactDefinition`，注册到宿主 `FactCatalog` 后再冻结；未注册 Fact、重复持久化 key、来源冲突会在 `DefaultMonitoringRuntime` 创建时拒绝。定义中的 codec 是写入 `monitoring_security_event_fact` 的唯一编码路径，禁止以任意 `toString()` 代替。

```java
@Bean
FactBinding invoiceFacts(InvoiceFactProvider provider) {
    return FactBinding.forAction(InvoiceExport.class, FactSource.HOST_PROVIDER, provider,
        BuiltInFacts.ResourceId.class, BuiltInFacts.DataCount.class);
}
```

绑定到 Contract 时会显式覆盖所有实现该 Contract 的 Action。Provider 返回未声明 Fact、多个来源写同一 Fact、类型错误或来源不被 Action 接受时，运行时拒绝该次调用。

`HOST_PROVIDER` 表示宿主服务端事实；`CLIENT_SUPPLEMENTAL` 只能用于 Action 明确允许的非权威补充信息。规则还会再次验证自己接受的来源。

### 先确定由谁决定

Starter 的全局 Web 设施只采集请求上下文；它不会把每个请求自动解释成业务 Action。宿主必须按真实决策点选择入口：

| 场景 | 责任方 | 推荐入口 |
| --- | --- | --- |
| IP、request ID、trace ID、已认证身份 | 宿主认证和可信代理配置，Starter 负责适配 | `MonitoringContextAccessor` |
| 无额外规则 Fact 的固定 MVC 动作 | 宿主声明动作，Starter 监听完成结果 | `@MonitorAction` |
| 登录、导出、资源范围、权限变化等规则依据 | 宿主业务 Service | `MonitoringService.monitor(ActionExecution)` |
| 可从稳定方法参数提取的单一事实 | 宿主显式声明参数路径 | `@ActionFact` |
| 同一 Action/Contract 的可复用服务端事实 | 宿主注册唯一生产者 | `FactBinding` |
| 限流、撤销会话、MFA、审批等副作用 | 宿主控制设施 | `ControlHandler` 或 `@ControlTrigger` |

`ActionFactProvider` 只计算值，`FactBinding` 决定其适用于具体 Action 还是共享 Contract；同一 Action/Fact 组合只能有一个生产者。业务上没有稳定、可信提取路径时，应显式调用程序化入口，不能为了“自动化”扫描任意请求体或响应体。

### 程序化入口

Service、消息消费和任务应调用 `MonitoringService.monitor(ActionExecution)`。调用方必须提供服务端构造的 `MonitoringRequestContext`、`IdentityContext`、`ActionOutcome` 和 Fact 来源。

### MVC 入口

Spring3 的六个路由对照见 [MonitoringFixtureController.java](../integration-audit/spring3-web/src/main/java/io/github/jasper/monitoring/audit/spring3/monitoring/MonitoringFixtureController.java)，请求 DTO 见 [AuditExportRequest.java](../integration-audit/spring3-web/src/main/java/io/github/jasper/monitoring/audit/spring3/monitoring/AuditExportRequest.java)。其中五个路由展示业务采集或结果处理方式，`contextOnly` 是“只有上下文、没有业务事件”的反例。阅读顺序是：先看 `contextOnly`，再看 `annotatedQuery` 的纯注解入口，最后比较 `annotatedExport` 的参数 Fact 和 `export` 的服务端显式 Fact。
```java
@MonitorAction(BuiltInActions.Query.class)
@GetMapping("/orders")
public List<Order> list() {
    return orderService.list();
}
```

`@MonitorAction` 只监听显式标注的方法，不扫描未标注参数、任意请求体或响应体。参数上显式声明 `@ActionFact` 时，切面按受限公共属性路径提取已注册 Fact，并标记为 `METHOD_PARAMETER`；声明、来源和重复生产者冲突在契约校验时拒绝。实际返回条数、导出结果和事务结果等执行后事实必须通过程序化入口提交。

`instrumentation.enabled=false` 时注解监听不注册；程序化入口、认证鉴权和宿主控制不应依赖这个开关。即使启用，未标注的方法也不会产生业务事件。

### 资源授权

`ResourceAccessGuard` 委托宿主 `ResourceScopeAuthorizer`，并用强类型 Action 记录允许或拒绝。未配置、返回空值或抛异常时默认拒绝；监测写入失败不能把拒绝改为允许。宿主必须在业务副作用前调用 Guard 并消费决定。

## 4. 规则模式、全局模式和控制

规则级 `DISABLED` 不评估；`OBSERVE` 只写 `monitoring_rule_observation`；`ALERT_ONLY` 生成告警和通知但不控制；`ENFORCE` 生成告警和通知，并仅在全局模式也为 `ENFORCE` 时执行控制。全局 `OBSERVE` 是部署安全上限，不关闭宿主认证、授权或事件采集。默认内置规则均为规则级 `ENFORCE`，所以全局 `OBSERVE` 下仍生成告警，但没有控制副作用。

全局 `ENFORCE` 在启动期扫描内置规则控制集合，当前要求可执行处理器覆盖：

- `REQUIRE_CAPTCHA`
- `RATE_LIMIT`
- `REVOKE_SESSION`
- `REQUIRE_MFA`
- `DENY`
- `REQUIRE_APPROVAL`

只返回 `SKIPPED` 的默认处理器不算能力。缺少任一类型时以 `ENFORCEMENT_HANDLER_REQUIRED` 拒绝启动。

宿主可实现 `ControlHandler`，也可在 Spring Bean 的公开方法使用 `@ControlTrigger`。处理器必须：

- 按 `ControlCommand.idempotencyKey` 去重；
- 验证 `ruleId`、主体类别和过期时间；
- 不声称支持尚未实现的动作；
- 返回明确成功、失败或跳过结果；
- 能承受重试和进程重启。

注解方法必须是 `public`，恰好接收一个 `ControlCommand`，并返回 `void` 或 `ControlExecution`；同一动作只能绑定一次，禁止绑定仅用于留证的 `RECORD`。

### 默认内置规则

| 规则 | Action/条件 | 默认控制 |
| --- | --- | --- |
| AUTH-01/02/03 | 登录失败 5 次/5 分钟；同 IP 10 账号/10 分钟且失败率 80%；停用账号 | 验证码+限流；限流；拒绝 |
| SESS-01 | 并发会话不少于 3 且来源网段不同 | MFA |
| AUTHZ-01/02 | 拒绝 10 次/5 分钟；顺序访问 100 个资源/10 分钟 | 限流；拒绝+撤销会话 |
| DATA-01/02/03 | 查询 120 次/5 分钟；1000 对象/30 分钟；非工作时段敏感对象 50 个 | 限流；拒绝+审批；MFA |
| EXPT-01/02 | 单次不少于 5000 或高敏；当日不少于 10000 或基线倍数不少于 3 | 拒绝+审批；拒绝 |
| PRIV-01/02 | 自授权；创建/授予高权限管理员 | 拒绝；MFA+审批 |
| SECU-01 | 规则、审计或安全开关变更 | `RECORD` 留证，不属于六类宿主副作用 |

`@ControlTrigger` 只声明“该宿主方法能够执行某类控制”，不负责规则判定，也不是权限校验的第二入口。明确的权限拒绝应由认证/授权中间件直接 fail-closed；监测组件记录拒绝事实并据此告警或追加控制，不能先放行业务再依靠控制器补救。

控制状态、版本和尝试历史由 MyBatis 持久状态机维护。需要审批的控制先进入等待状态；管理服务负责批准、拒绝和失败重试。

### 内置控制触发器清单

当前内置规则会产生六类必须由宿主提供实际副作用的动作。Spring3 验收实现见 [AuditControlActions.java](../integration-audit/spring3-web/src/main/java/io/github/jasper/monitoring/audit/spring3/control/AuditControlActions.java)；该类使用 `audit_control_state` 和 `audit_session` 作为测试替身。

| 控制动作 | 当前触发规则 | 宿主副作用含义 | 集成者必须确认 |
| --- | --- | --- | --- |
| REQUIRE_CAPTCHA | AUTH-01 | 下一次敏感操作前要求挑战 | 挑战状态绑定到命令 subject；重放不重复创建或延长状态 |
| RATE_LIMIT | AUTH-01、AUTH-02、AUTHZ-01、DATA-01 | 限制账号、会话或 IP 的后续请求频率 | 使用命令 subject 的实际作用域；不能把账号级命令错误套到全局 IP |
| REVOKE_SESSION | AUTHZ-02 | 使命令 subject 的活跃会话失效 | 会话服务完成批量撤销；成功重放不重复撤销或延长 TTL |
| REQUIRE_MFA | SESS-01、DATA-03、PRIV-02 | 要求更强认证步骤 | MFA 状态必须能被后续认证流程消费，而不是只写一条日志 |
| DENY | AUTH-03、AUTHZ-02、DATA-02、EXPT-01、EXPT-02、PRIV-01 | 拒绝指定主体或资源范围的后续操作 | 拒绝发生在业务副作用前；宿主仍是最终授权者 |
| REQUIRE_APPROVAL | DATA-02、EXPT-01、PRIV-02 | 将操作置于宿主审批流程 | 审批对象、操作者、资源和幂等键可追溯；审批前不生成受保护业务结果 |

RECORD 由组件直接保留规则观察或管理审计证据，不要求宿主控制处理器。LOCK 是 API 支持的控制类型，但当前十四条内置规则没有产生 LOCK；只有规则目录实际声明 LOCK 时，ENFORCE 才会要求对应处理器。

控制触发器的声明方式、运行时检查和结果含义见 [ControlTrigger.java](../api/src/main/java/io/github/jasper/monitoring/api/ControlTrigger.java)、[ControlHandler.java](../core/src/main/java/io/github/jasper/monitoring/core/port/ControlHandler.java) 和 [ControlActionType.java](../api/src/main/java/io/github/jasper/monitoring/api/ControlActionType.java)。声明方法必须是 public、只接收一个 ControlCommand，并返回 void 或 ControlExecution；同一动作只能有一个绑定，RECORD 不应声明为宿主触发器。

### Starter 自动提供与集成者 Bean 清单

| Bean/接口 | Starter 当前行为 | 集成者是否必须补充 |
| --- | --- | --- |
| SqlSessionFactory | 没有时启动失败；MyBatis 仓储依赖它 | 必须提供，并执行 monitoring-schema.sql |
| IdentityContextProvider | 默认返回 anonymous | 真实身份接入必须替换默认实现 |
| ResourceScopeAuthorizer | 默认明确拒绝 | 需要资源授权时必须实现；不能依赖默认放行 |
| TrustedProxyResolver | 按 trusted-proxies 配置创建 | 配置可信代理即可；需要自定义代理链时替换 Bean |
| MonitoringContextAccessor | Servlet 应用自动创建 | 只有非标准请求上下文或需要自定义适配时替换 |
| NotificationChannel | 默认 noop，只保存投递状态不发送外部通知 | 需要真实通知时实现；不要把 noop 当成通知已送达 |
| ControlHandler 或 ControlTrigger Bean | 默认回退触发器只记录 SKIPPED | ENFORCE 必须为上表六类动作提供可执行实现 |
| ManagementAuthorizer | 没有默认 Bean，因而不创建管理服务 | 需要管理查询、处置、规则、白名单或控制 API 时必须提供 |
| FactBinding | 默认没有宿主 Fact 生产者 | 需要复用计算逻辑时按 Action 或 Contract 注册唯一绑定 |
| MonitoringService、ActionCatalog、FactCatalog、RuleCatalog | Starter 自动创建并冻结内置目录 | 只在自定义运行时装配时替换；替换后必须保持冻结和完整校验 |
| FrontendSignalRecorder | Starter 自动创建 | 仅在接收已通过 web-contract 校验的前端补充信号时使用 |

上述默认 Bean 的创建逻辑见 [AbnormalAccessMonitorAutoConfiguration.java](../spring3-starter/src/main/java/io/github/jasper/monitoring/spring3/autoconfigure/AbnormalAccessMonitorAutoConfiguration.java)。默认 anonymous、deny、noop 和 fallback 都是安全占位，不代表宿主已经接入真实能力。

### 扩展实现细节：自定义监听、触发器和规则

本节补充上一节的快速规则，说明扩展点的注册边界、运行时装配限制和当前内置实现清单。

#### 自定义监听

自定义 Action 应定义为具体 final 类，使用 lowercase domain:verb 编码，并注册到 ActionCatalog。自定义 Fact 应有唯一 FactDefinition，注册到 FactCatalog；需要复用计算时再提供 ActionFactProvider 和唯一 FactBinding。目录在运行时创建前完成注册并 freeze。

    public final class InvoiceExport implements ActionType {
        private InvoiceExport() { }
    }

    @Bean
    FactBinding invoiceFacts(InvoiceFactProvider provider) {
        return FactBinding.forAction(InvoiceExport.class, FactSource.HOST_PROVIDER,
            provider, InvoiceFacts.RowCount.class, BuiltInFacts.ResourceId.class);
    }

动作定义、事实定义和绑定的参考位置：

- [BuiltInActions.java](../api/src/main/java/io/github/jasper/monitoring/api/action/BuiltInActions.java)
- [BuiltInFacts.java](../api/src/main/java/io/github/jasper/monitoring/api/fact/BuiltInFacts.java)
- [FactBinding.java](../api/src/main/java/io/github/jasper/monitoring/api/fact/FactBinding.java)
- [MonitoringService.java](../core/src/main/java/io/github/jasper/monitoring/core/application/MonitoringService.java)

#### 自定义控制处理器

当前 ControlActionType 是固定枚举，扩展点是为已有控制类型接入宿主副作用，不是通过字符串增加新的控制类型。可以直接实现 ControlHandler，也可以在 Spring Bean 的 public 方法上使用 ControlTrigger。处理器必须验证 subject、ruleId、expiresAt 和 idempotencyKey，并能承受重复调用、进程重启和下游超时。

当前实现没有把“新增一个自定义枚举控制动作”作为 Starter 插件能力；若确实需要新控制语义，需要同时扩展 API 枚举、控制目录、规则定义、持久化和验收测试，不能只增加一个注解方法。

#### 自定义规则

规则必须使用 final 的 RuleType token 和唯一规则 ID，通过 RuleDefinition 声明：

1. 适用的 Action 或 ActionContract；
2. 必需 Fact 及允许来源；
3. 时间窗口和正整数阈值；
4. 风险等级、RuleMode 和 RuleSource；
5. 命中后要求的 ControlActionType。

无状态条件可使用 EventConditionRule，窗口计数、资源去重和 data_count 累加可使用 WindowAggregateRule；更复杂的关联逻辑实现 DetectionRule.evaluate，但只能读取标准化 SecurityEvent 和 RuleEvaluationContext，不应读取原始请求体或直接执行宿主副作用。规则只返回 RuleMatch，告警、通知和控制由 TypedRuleEvaluationService 统一处理。

规则定义和实现参考：

- [RuleDefinition.java](../api/src/main/java/io/github/jasper/monitoring/api/rule/RuleDefinition.java)
- [RuleCatalog.java](../api/src/main/java/io/github/jasper/monitoring/api/rule/RuleCatalog.java)
- [DetectionRule.java](../core/src/main/java/io/github/jasper/monitoring/core/domain/rule/DetectionRule.java)
- [EventConditionRule.java](../core/src/main/java/io/github/jasper/monitoring/core/domain/rule/EventConditionRule.java)
- [WindowAggregateRule.java](../core/src/main/java/io/github/jasper/monitoring/core/domain/rule/WindowAggregateRule.java)

重要限制：当前 Spring2/Spring3 Starter 默认的 TypedRuleEvaluationService 直接装配 DefaultRuleCatalog.typedRules()。因此“只声明一个自定义 RuleType Bean”目前不会自动加入运行时评估。自定义规则目前可在 core 层直接组装 TypedRuleEvaluationService，或通过自定义 MonitoringService.RuleEvaluationPort/Starter 自动配置完成完整替换；替换时必须同时保证规则目录、控制覆盖和管理查询看到的是同一份冻结定义。不要仅向数据库写一条规则记录就认为运行时已启用。

## 5. 管理服务接入

宿主必须提供可信的 `ManagementAuthorizer` Bean。Starter 才会创建五个管理服务；没有默认放行实现。

```java
@RestController
final class MonitoringEventController {
    private final SecurityEventQueryService events;

    MonitoringEventController(SecurityEventQueryService events) {
        this.events = events;
    }

    @GetMapping("/management/monitoring/events")
    ManagementPage<SecurityEventView> search(SecurityEventQuery query,
                                              AuthenticatedAdmin admin) {
        ManagementActor actor = ManagementActor.of(admin.id(), admin.systemId());
        return events.search(actor, query);
    }
}
```

Controller 负责从服务端认证上下文创建 `ManagementActor`，不能信任请求体中的 actor 或 systemId。服务内部固定使用构造时绑定的授权器，并写入 `monitoring_management_audit`：操作、资源、结果、操作者、系统范围和时间。

告警、白名单和控制变更使用版本号进行乐观锁校验。冲突必须返回宿主统一的 409/业务错误，不能静默覆盖。

## 6. 前端补充信号

宿主自行定义接收 URL、认证、限流和响应格式。请求体先用 `web-contract` 的 JSON Schema 校验，再由服务端补充可信身份、IP、请求 ID 和 trace ID，最后调用 `FrontendSignalRecorder`。

`FrontendSignal` 是独立 Action，不绑定任何内置规则。浏览器字段不能触发内置控制，也不能覆盖身份、角色、资源授权或源 IP。

## 8. 接入验收

- 缺少 `SqlSessionFactory` 时启动失败。
- Action 目录冻结，未知 Action 和不合法 Fact 在调用前失败。
- MyBatis 中可查到事件、告警、控制和管理审计。
- 跨系统管理调用被拒绝并留下 `DENIED` 审计。
- 当前事件经过数据库时间精度转换后仍参与窗口规则。
- 控制成功、失败、审批、重试和幂等重放均有测试。
- Boot 2/3 行为对称。
- `mvn clean verify -DskipTests=false` 通过。

故障定位和事务边界见[架构与运维说明](架构与运维说明.md)，可复现验收见[集成审计与基础项目验收](集成审计与基础项目验收.md)。
