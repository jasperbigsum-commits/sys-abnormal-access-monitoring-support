# 集成指南

本文面向宿主系统和管理端开发者。组件不接管认证、业务授权、Controller URL 或前端；它提供可组合的强类型契约和 Spring Bean。

## 1. 安装顺序

1. Boot 2.7 使用 `spring2-starter`，Boot 3 使用 `spring3-starter`，不要同时引入。
2. 用宿主迁移工具执行 `mybatis/src/main/resources/db/monitoring-schema.sql`。
3. 确认应用存在可用的 `SqlSessionFactory`。缺失时 Starter 必须启动失败。
4. 设置稳定 `system-id`，先使用 `OBSERVE`。
5. 注册可信身份、资源授权、代理解析和通知适配。
6. 验证事件、告警、控制、管理授权和审计后再评估 `ENFORCE`。

组件不会自动建表，也没有生产内存回退。H2 仅用于测试。

## 2. Action 和 Fact

### 内置 Action

`BuiltInActions` 提供登录失败、查询、敏感查看、报表导出、权限变更、安全配置变更、授权允许/拒绝和前端补充信号等类型。每个类型均对应一个冻结的 `ActionDefinition`。

### 自定义 Action

自定义 Action 必须是具体 `final` 类。需要共享语义时实现公开 `ActionContract`，不要通过字符串前缀或继承猜测关系。

```java
public interface BulkRead extends ActionContract { }

public final class InvoiceExport implements ActionType, BulkRead {
    private InvoiceExport() { }
}
```

在 `ActionCatalog` 中注册编码、事件类型、资源类型、Fact、规则和失败策略，并在创建运行时前 `freeze()`。重复类型、重复编码、抽象 Action 和冻结后变更都会失败。

### Fact Provider 的归属

`ActionFactProvider` 只负责从只读 `ActionExecution` 产生 Fact；`FactBinding` 才拥有适用范围：

自定义 Fact 还必须提供唯一 `FactDefinition`，注册到宿主 `FactCatalog` 后再冻结；未注册 Fact、重复持久化 key、来源冲突会在 `DefaultMonitoringRuntime` 创建时拒绝。定义中的 codec 是写入 `security_event_fact` 的唯一编码路径，禁止以任意 `toString()` 代替。

```java
@Bean
FactBinding invoiceFacts(InvoiceFactProvider provider) {
    return FactBinding.forAction(InvoiceExport.class, FactSource.HOST_PROVIDER, provider,
        BuiltInFacts.ResourceId.class, BuiltInFacts.DataCount.class);
}
```

绑定到 Contract 时会显式覆盖所有实现该 Contract 的 Action。Provider 返回未声明 Fact、多个来源写同一 Fact、类型错误或来源不被 Action 接受时，运行时拒绝该次调用。

`HOST_PROVIDER` 表示宿主服务端事实；`CLIENT_SUPPLEMENTAL` 只能用于 Action 明确允许的非权威补充信息。规则还会再次验证自己接受的来源。

## 3. 监测入口

### 程序化入口

Service、消息消费和任务应调用 `MonitoringService.monitor(ActionExecution)`。调用方必须提供服务端构造的 `MonitoringRequestContext`、`IdentityContext`、`ActionOutcome` 和 Fact 来源。

### MVC 入口

```java
@MonitorAction(BuiltInActions.Query.class)
@GetMapping("/orders")
public List<Order> list() {
    return orderService.list();
}
```

注解只选择已注册的 Action 类型。切面记录完成结果，不负责业务前置授权，也不读取方法参数或载荷。需要规则 Fact 的动作优先使用程序化入口。

### 资源授权

`ResourceAccessGuard` 委托宿主 `ResourceScopeAuthorizer`，并用强类型 Action 记录允许或拒绝。未配置、返回空值或抛异常时默认拒绝；监测写入失败不能把拒绝改为允许。宿主必须在业务副作用前调用 Guard 并消费决定。

## 4. ENFORCE 和控制

`OBSERVE` 记录事件、评估规则并生成告警，但不执行控制。`ENFORCE` 在启动期扫描内置规则的控制集合，当前要求可执行处理器覆盖：

- `REQUIRE_CAPTCHA`
- `RATE_LIMIT`
- `REVOKE_SESSION`
- `REQUIRE_MFA`
- `DENY`
- `REQUIRE_APPROVAL`

只返回 `SKIPPED` 的默认处理器不算能力。缺少任一类型时以 `ENFORCEMENT_HANDLER_REQUIRED` 拒绝启动。

宿主可实现 `ControlHandler`，也可在 Spring Bean 的公开方法使用 `@ControlTrigger`。处理器必须：

- 按 `ControlCommand.idempotencyKey` 去重；
- 验证 `ruleId`、主体类别和过期时间；
- 不声称支持尚未实现的动作；
- 返回明确成功、失败或跳过结果；
- 能承受重试和进程重启。

控制状态、版本和尝试历史由 MyBatis 持久状态机维护。需要审批的控制先进入等待状态；管理服务负责批准、拒绝和失败重试。

## 5. 管理服务接入

宿主必须提供可信的 `ManagementAuthorizer` Bean。Starter 才会创建五个管理服务；没有默认放行实现。

```java
@RestController
final class MonitoringEventController {
    private final SecurityEventQueryService events;

    MonitoringEventController(SecurityEventQueryService events) {
        this.events = events;
    }

    @GetMapping("/management/monitoring/events")
    ManagementPage<SecurityEventView> search(SecurityEventQuery query,
                                              AuthenticatedAdmin admin) {
        ManagementActor actor = ManagementActor.of(admin.id(), admin.systemId());
        return events.search(actor, query);
    }
}
```

Controller 负责从服务端认证上下文创建 `ManagementActor`，不能信任请求体中的 actor 或 systemId。服务内部固定使用构造时绑定的授权器，并写入 `management_audit`：操作、资源、结果、操作者、系统范围和时间。

告警、白名单和控制变更使用版本号进行乐观锁校验。冲突必须返回宿主统一的 409/业务错误，不能静默覆盖。

## 6. 前端补充信号

宿主自行定义接收 URL、认证、限流和响应格式。请求体先用 `web-contract` 的 JSON Schema 校验，再由服务端补充可信身份、IP、请求 ID 和 trace ID，最后调用 `FrontendSignalRecorder`。

`FrontendSignal` 是独立 Action，不绑定任何内置规则。浏览器字段不能触发内置控制，也不能覆盖身份、角色、资源授权或源 IP。

## 7. Maven 初始化模板

```bash
mvn io.github.jasperbigsum-commits:sys-abnormal-access-monitoring-maven-plugin:1.0.0-SNAPSHOT:initialize \
  -Dmonitoring.packageName=com.example.monitoring \
  -Dmonitoring.systemId=order-service
```

模板生成强类型 `ActionCatalog`、`FactBinding`、宿主 SPI、控制处理器和配置示例。模板中的匿名身份、默认拒绝和未实现控制是待完成的安全占位，不可直接用于生产。

## 8. 接入验收

- 缺少 `SqlSessionFactory` 时启动失败。
- Action 目录冻结，未知 Action 和不合法 Fact 在调用前失败。
- MyBatis 中可查到事件、告警、控制和管理审计。
- 跨系统管理调用被拒绝并留下 `DENIED` 审计。
- 当前事件经过数据库时间精度转换后仍参与窗口规则。
- 控制成功、失败、审批、重试和幂等重放均有测试。
- Boot 2/3 行为对称。
- `mvn clean verify -DskipTests=false` 通过。

故障定位和事务边界见[架构与运维说明](架构与运维说明.md)，可复现验收见[集成审计与基础项目验收](集成审计与基础项目验收.md)。
