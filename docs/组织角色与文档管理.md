# 组织角色与文档管理

本文是项目文档的治理入口。文档按责任人组织，描述“谁在什么阶段做什么、交付什么证据”；设计稿只解释决策背景，不替代本规范。

## 角色与责任

| 角色 | 负责范围 | 必须交付 |
| --- | --- | --- |
| 宿主系统负责人 | 身份、资源授权、代理信任、前端接收端、控制执行 | SPI 实现、配置、控制处理器验收记录 |
| 业务负责人 | 正常访问基线、敏感等级、阈值和审批策略 | 业务场景表、阈值与敏感度确认记录 |
| 组件维护者 | `api` 契约、`core` 规则与用例、版本兼容 | API 变更说明、单元测试、迁移说明 |
| 持久化负责人 | MyBatis Mapper、Schema、事务和索引 | 迁移脚本、Mapper 集成测试、回滚方案 |
| 管理端负责人 | 查询、告警处置、规则/白名单/控制管理接口 | Controller 适配、授权接入、接口验收证据 |
| 安全与审计负责人 | 数据最小化、审计完整性、ENFORCE 放行 | 风险评估、敏感字段检查、上线签字 |
| 测试负责人 | TC/IA 编号、场景数据、对称回归和证据可复现 | 用例矩阵、Surefire 报告、缺陷闭环 |
| 运维负责人 | 发布、监控、故障恢复和留存 | 发布清单、值守指标、演练记录 |

职责不得交叉替代：宿主决定身份和实际控制，组件只提供契约和确定性判定；管理端不能绕过授权直接改写运行时规则；运维不能以配置覆盖安全负责人未批准的 ENFORCE 决策。

## 变更流程

1. 提出者在对应入口文档登记影响模块、兼容性和验收标准。
2. 组件维护者确认 API/规则边界；持久化负责人确认 Schema 与事务；安全与审计负责人确认数据和放行风险。
3. 代码、测试、迁移和文档同一变更提交；文档不得描述未实现能力。
4. 执行 `mvn clean verify -DskipTests=false`，在集成审计模块补充可复现证据。
5. 发布后由运维负责人归档版本、迁移结果和回滚点。

## 生产硬约束

- 生产只使用 MyBatis 持久化；未配置 `SqlSessionFactory` 必须启动失败，不提供内存回退。
- 全局 `OBSERVE` 允许事件、规则告警和通知但禁止控制副作用；`ENFORCE` 必须覆盖全部内置规则控制类型，并支持幂等重放。
- 身份、授权、客户端 IP 和最终控制结论只来自服务端可信上下文；前端信号仅为补充证据。
- 事件、告警、控制和处置写入遵循事务边界；外部通知/控制在提交后执行。
- 禁止写入密码、令牌、Cookie、密钥及未经批准的原始请求/响应载荷。

## 最小验收证据

上线前必须能够关联以下证据：Schema 迁移成功、事件和告警可查询、管理接口授权拒绝用例、控制成功/失败/超时/重复投递用例、敏感字段拦截用例，以及故障时的安全默认行为。缺一项不得切换 `ENFORCE`。
