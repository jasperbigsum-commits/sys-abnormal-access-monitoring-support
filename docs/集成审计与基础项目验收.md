# 集成审计与基础项目验收

`integration-audit` 是两个完整、可启动的最小 Spring Boot Web 宿主项目，不是仅引用核心类的测试模块。它们使用真实嵌入式 Tomcat、Starter 自动装配、H2/MyBatis 审计表、HTTP 路由和宿主控制处理器，作为升级、风险排查与修复回归的可复现依据。

```text
integration-audit/
  spring2-web/   Spring Boot 2.7.18, javax.servlet, Java 8
  spring3-web/   Spring Boot 3.2.12, jakarta.servlet, Java 17
```

两个项目分别使用 `audit-spring2` 与 `audit-spring3` H2 内存库，不共享类路径、Servlet API 或数据源。它们的 `ENFORCE` 配置仅用于演示，控制处理器只返回成功记录，不会锁定真实账号、调用外部限流或连接生产系统。

## 运行与测试

在当前 Reactor 中先构建所需上游模块，再执行对应 Web 项目的验收：

```bash
mvn -pl integration-audit/spring2-web -am test
mvn -pl integration-audit/spring3-web -am test
```

本地交互启动时，先安装当前快照，再选择一个项目运行：

```bash
mvn -pl integration-audit/spring2-web -am -DskipTests install
mvn -pl integration-audit/spring2-web spring-boot:run
```

将第二条命令中的 `spring2-web` 替换为 `spring3-web` 即可启动 Boot 3。应用启动后可调用：

| 路由 | 埋点方式 | 验收目的 |
| --- | --- | --- |
| `POST /audit/login-failure` | 注册式 `ActionEventRecorder.record(...)` | 连续 5 次触发 `AUTH-01`，生成告警、验证码和限流控制记录。 |
| `POST /audit/export` | 注册式 `draft(...)` 补充资源 ID 与导出量 | 触发 `EXPT-01`，验证规则标记、动态事实和 MyBatis 属性映射。 |
| `GET /audit/annotated-query` | `@MonitorAction` 全局 MVC 拦截 | 验证注解静态元数据和请求完成后审计。 |

## 审计证据与定位

每个项目的 Surefire XML 与文本报告位于：

- `integration-audit/spring2-web/target/surefire-reports/`
- `integration-audit/spring3-web/target/surefire-reports/`

三项 HTTP 验收均从响应状态、事件、告警和控制持久化结果交叉取证。若登录失败事件存在而第 5 次没有命中，检查事件类别、身份上下文、窗口历史和 `AUTH-01` 阈值；有命中但没有控制记录，检查 `mode=ENFORCE` 与宿主 `ControlHandler` 支持的动作。导出事件缺少属性时，检查 `MonitoringActionRegistry` 和 `ActionEventRecorder.draft(...)`。注解事件缺失时，检查 `instrumentation.enabled`、MVC 自动装配和 `@MonitorAction` 是否标在控制器方法或类型上。

本项目已覆盖数据库时间精度风险：持久化回读的当前事件会按事件 ID 恢复为原始内存事件，确保数据库截断/舍入 `Instant` 后，当前事件仍参与窗口规则计算。验收仅使用 H2，不能替代目标数据库并发、生产授权、真实控制副作用或数据留存验证；这些应由宿主在目标环境补充。
