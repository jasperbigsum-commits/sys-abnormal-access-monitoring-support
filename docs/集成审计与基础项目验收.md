# 集成审计与基础项目验收

本文把《自建系统异常访问监测与控制建设方案（方案 A）》附录 B 的最低用例落实为可重复执行的集成审计。`spring2-web` 和 `spring3-web` 是独立宿主样例，分别验证 Boot 2/`javax.servlet` 与 Boot 3/`jakarta.servlet`。二者使用真实嵌入式 Web 容器、Starter、MyBatis、H2、Shiro 测试身份和宿主控制 Bean。

H2、固定身份、模拟通知和控制动作只用于验收，不是生产认证、数据库、通知或控制实现。

## 1. 执行与完整性门禁

```bash
mvn -pl integration-audit/spring2-web -am test
mvn -pl integration-audit/spring3-web -am test
mvn clean verify -DskipTests=false
```

Surefire 证据位于各宿主的 `target/surefire-reports/`。`integration-audit` 的 `verify` 阶段还会执行验收编号门禁：Boot 2 和 Boot 3 必须各自、唯一且完整地覆盖 `TC-01` 至 `TC-18` 与 `IA-01` 至 `IA-12`；遗漏、重复或两端不对称都会使构建失败。

## 2. 采集与触发边界

方案 A 要求认证鉴权中间件先确定身份、会话、角色和资源范围，再由公共采集器形成事件。组件据此划分四层入口：

| 层次 | 默认提供者 | 能获得什么 | 不能替代什么 |
| --- | --- | --- | --- |
| 请求上下文采集 | Starter 全局 MVC `HandlerInterceptor`/上下文访问器 | 可信代理解析后的 IP、request ID、trace ID、宿主身份上下文 | 不代表发生了登录、查询、导出或权限变更 |
| 固定动作监听 | 启用 `instrumentation` 后的 `@MonitorAction` 切面 | 方法动作、耗时以及成功/拒绝/失败结果 | 不读取请求体、响应体或任意方法参数，不猜测业务 Fact |
| 业务事实埋点 | 宿主服务调用 `MonitoringService`，或显式声明 `@ActionFact`/`FactBinding` | 数据量、资源、组织范围、权限增量、敏感等级等服务端事实 | 客户端字段不能覆盖服务端身份、授权和控制依据 |
| 控制触发 | 内置规则产生 `ControlCommand`，宿主 `ControlHandler` 或 `@ControlTrigger` 执行 | 幂等键、主体、规则、动作和有效期 | 默认 `SKIPPED` 触发器不是 ENFORCE 能力，不执行宿主副作用 |

因此，“全局监听”只建立可信请求上下文并适配已声明动作，不会自动理解所有业务。登录、资源授权、查询、导出、权限变更、安全配置变更和会话撤销必须在宿主真实决策点埋入强类型动作与事实。规则和阈值可以内置，事实来源不能伪造。

启动时会扫描并冻结 Action、Fact、规则与控制绑定。未知 Action、Fact 所有权冲突、非法/重复 `@ControlTrigger`、以及 ENFORCE 缺少真实处理器都会拒绝启动。

## 3. 方案 A 最低用例矩阵

下表的“必须结果”是宿主最终验收目标，不等同于仅凭测试类名即已证明。当前自动化使用同编号 `@DisplayName`，并分别在 Boot 2/3 同名 `*AcceptanceTest` 中断言 HTTP、数据库和业务状态；真实身份、目标数据库、通知渠道、控制设施、性能和运维演练仍属于第 5 节的宿主证据。

| 用例 | 责任人 | 模拟业务场景与入口 | 方案 A 必须结果 |
| --- | --- | --- | --- |
| TC-01 | 认证开发/测试 | 5 分钟内同账号五次登录失败；认证服务向 `AuthenticationMonitor` 传入 `LoginSubjectInput` 和规范原因码 | `AUTH-01` 告警；opaque subject 持久化；验证码/限流控制；下一请求受控 |
| TC-02 | 认证开发/测试 | 同一可信来源尝试 10 个账号；认证服务 + 可信代理解析 | 高风险告警；只限制来源 IP，不误伤账号集合 |
| TC-03 | 认证开发/测试 | 停用账号提交登录；账号状态检查点 | 同步拒绝、高风险事件、无新会话 |
| TC-04 | 管理端开发/测试 | 普通用户直接调用管理接口；`ManagementAuthorizer` | HTTP 403、拒绝审计、业务状态不变 |
| TC-05 | 鉴权开发/测试 | 修改报告 ID 跨机构访问；资源 resolver 与授权阶段在 Controller 前执行 | 一致拒绝响应、不泄露资源详情、内部保留真实原因 |
| TC-06 | 业务开发/测试 | 顺序遍历大量资源 ID；资源授权失败埋点 | `AUTHZ-02` 告警并撤销/限制当前会话 |
| TC-07 | 业务开发/测试 | 用户达到查询窗口阈值；查询服务提交服务端事实 | 告警、用户/接口限流、统一受控响应 |
| TC-08 | 导出开发/测试 | 单次导出超过 5000 行；先计数和预检再生成文件 | XLSX 前阻断、审批控制、条件摘要和数量 |
| TC-09 | 导出开发/测试 | 多次小额导出使当日累计越线；MyBatis 台账 | 命中累计规则，越线请求不生成文件 |
| TC-10 | 权限开发/测试 | 管理员为本人提升权限；角色事务提交前检查 | 403、事务回滚、`PRIV-01` 告警和 `DENY` 控制 |
| TC-11 | 会话开发/测试 | 停用账号或人工撤销会话；授权管理服务 | 相关会话失效，结果与幂等键持久化；越权无副作用 |
| TC-12 | 安全管理/测试 | 有效白名单到期后再次触发；MyBatis 白名单 | 有效期内抑制；过期后恢复告警 |
| TC-13 | 控制开发/测试 | 并发重复投递同一命令；宿主按幂等键执行 | 只执行一次，控制 TTL 不被重复延长 |
| TC-14 | 通知开发/测试 | 通知渠道前两次失败；提交后通知 + 持久重试 | 业务/告警不回滚；有限重试后送达；告警不重复 |
| TC-15 | 安全/测试 | 登录、导出和错误请求含伪造敏感值 | HTTP、数据库文本列和日志均无密码、Token、Cookie、密钥原文 |
| TC-16 | 安全管理/测试 | 独立申请人和审批人变更规则 | 新版本追加；值、双方身份和时间齐全；旧版本保留 |
| TC-17 | 运维/测试 | 从全局 ENFORCE 回退到 OBSERVE；同一业务场景 | 停止新增控制，但认证鉴权、事件和告警继续工作 |
| TC-18 | 安全运营/测试 | 确认、分派、调查并关闭；管理服务 | 追加时间线、责任人、结论；过期版本/越权无状态变化 |

## 4. 组件契约审计

| 编号 | 集成契约 | 自动化证据 |
| --- | --- | --- |
| IA-01 | 生产持久化只有 MyBatis | 实际 Bean 类型和 SQL 事件/告警/控制计数 |
| IA-02 | 仅建立请求上下文不产生业务事件 | 无 Action 的受理请求前后事件数不变 |
| IA-03 | 注解动作区分成功与拒绝 | 200 记 `SUCCESS`，403 记 `DENIED` |
| IA-04 | 普通 Service 注解作用域追加运行时 Fact | 客户端 `5000` 不覆盖服务端 `37`，`data_count` 来源为 `HOST_PROVIDER` |
| IA-05 | 客户端不能覆盖服务端 Fact | 伪造报告/数量与最终事件值不同 |
| IA-06 | Fact 生产者所有权唯一且冻结 | Action/Contract 重叠绑定在运行时创建前失败 |
| IA-07 | `@ResourceAccess` 资源授权阶段 fail-closed | Controller 前允许/拒绝及无信息泄露 |
| IA-08 | 控制触发器声明合法且唯一 | 非法签名、`RECORD`、重复动作拒绝 |
| IA-09 | ENFORCE 只接受真实宿主处理器 | fallback 或缺失能力不满足启动要求 |
| IA-10 | 规则与控制来自同一冻结目录 | 规则要求集合与可执行控制集合精确相等 |
| IA-11 | 管理身份由服务端派生并再次授权 | 跨系统/无权限 actor 拒绝并审计 |
| IA-12 | Boot 2/3 验收集合完全对称 | verifier 校验 30 个编号唯一、完整、同集 |

## 5. 上线仍需宿主提供的证据

本模块证明组件契约、自动配置、HTTP 适配和 MyBatis 能协作，但不能替代目标系统验收。宿主还必须提交：

- 关键接口、资源范围和批量接口的 100% 后端鉴权清单；
- 业务 Action/Fact/来源映射，以及监听、显式埋点和触发器配置表；
- 目标数据库迁移、索引、并发和备份恢复结果；
- 真实身份、会话、验证码、限流、MFA、审批、通知和紧急解锁演练；
- 2 至 4 周 OBSERVE 试运行数据、阈值三方确认和误报复核；
- 性能基线、事件字段完整率、敏感信息抽检和留存策略。

只有事件、规则、告警、控制和处置可以按 ID 串联，且 TC-01 至 TC-18 与宿主外部证据全部通过，才满足方案 A 的最低“发现、告警、控制、追溯”闭环。
