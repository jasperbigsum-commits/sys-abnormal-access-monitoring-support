# 集成审计管理端设计

**状态：** 2026-07-30 已确认，等待书面复核

## 目标

在 `integration-audit` 下新增可独立运行的 Vite + Vue 3 管理端，完整展示异常访问监测、告警处置、控制审批、规则治理、白名单和管理审计能力。管理端优先完成 Mock 全功能体验与视觉验收，再接入 Spring 3 集成审计宿主；Spring 2 保持同构 HTTP 契约。

管理端采用银行科技风控风格：深青色品牌导航、明亮高密度工作区、红色高危信号、琥珀色审批提示。设计服务于持续巡检、快速处置和合规追溯，不采用营销式大标题、装饰性卡片堆叠或全站深色主题。

## 范围与边界

- 新前端位于 `integration-audit/admin-web`，不加入 Maven reactor。
- 前端可通过 `VITE_DATA_MODE=mock|http` 切换数据源，页面不感知数据来源。
- 默认 Mock 模式无需 Java 服务即可运行全部查询和处置流程。
- HTTP 模式对接 `integration-audit/spring3-web`，该宿主作为主要联调和验收环境。
- Spring 2 暴露与 Spring 3 同构的管理路径和响应结构，但不承担前端主验收。
- 不引入完整 JeecgBoot 前端仓库。项目建立轻量 Jeecg 兼容组件层，复用其公开组件命名、注册式 Hook 和调用习惯。
- 前端身份只用于显示和权限体验；可信操作者、系统范围、组织范围和授权结果始终由服务端认证上下文派生。
- 前端遥测不作为服务端身份、资源范围或风险判定的权威事实。
- 前端不允许自建白名单主体、规则或 TTL，只能管理服务端预置条目的生命周期。

## 工程方案

采用“独立 SPA + Repository 双适配”方案。

```text
Views / Routes
  -> Jeecg-compatible UI components and hooks
  -> Pinia stores and domain composables
  -> MonitoringRepository
       -> MockMonitoringRepository
       -> HttpMonitoringRepository -> defHttp -> Spring management API
```

建议目录：

```text
integration-audit/admin-web/
  src/
    api/                 # defHttp、Result<T>、HTTP DTO 与接口函数
    components/jeecg/    # BasicTable、BasicForm、BasicModal、BasicDrawer 等兼容层
    domain/              # 页面使用的领域类型、字典和错误类型
    layouts/             # 风控中心主布局
    mocks/               # 确定性数据集、场景与 Mock Repository
    repositories/        # MonitoringRepository 及 mock/http 实现
    router/              # 路由、菜单和权限元数据
    stores/              # Pinia 状态
    views/               # 各业务页面
```

`MonitoringRepository` 公开分页查询、详情读取和领域命令，不公开 Axios 类型。Mock 与 HTTP 实现必须通过同一组 Repository 契约测试。页面不得根据 `VITE_DATA_MODE` 分支处理业务逻辑。

## Jeecg 兼容层

页面统一使用以下组件和组合方式：

| 能力 | 兼容接口 | 约束 |
| --- | --- | --- |
| 列表和分页 | `BasicTable`、`useTable`、`useListPage` | 查询、排序、选中、分页和刷新统一管理，页面不直接维护 Ant Design Vue 分页状态。 |
| 查询和编辑表单 | `BasicForm`、`useForm`、`FormSchema` | 字段、校验、重置和提交通过 schema 配置；仅无法由 schema 表达的复杂内容使用插槽。 |
| 弹窗 | `BasicModal`、`useModal` | 使用注册式 API，关闭时清理表单和异步状态。 |
| 抽屉 | `BasicDrawer`、`useDrawer` | 列表详情保持筛选和分页上下文。 |
| 字典显示 | `DictTag`、`JDictSelectTag` 兼容接口 | 风险、状态、模式、结果和控制类型使用统一字典。 |
| 权限体验 | `PermissionAction` 或 `v-auth` 兼容接口 | 只控制前端可见性，不代替服务端授权。 |
| 页面结构 | `PageWrapper` | 提供一致的标题、说明、工具栏和内容间距。 |

兼容层内部基于 Ant Design Vue 实现，但业务页面不直接拼装分页、表单注册、Modal 或 Drawer 生命周期。接口优先保持 Jeecg 迁移友好，不复制与本项目无关的完整框架功能。

## 信息架构

| 一级页面 | 核心能力 | 写操作 |
| --- | --- | --- |
| 风险态势 | 风险指标、24 小时趋势、规则贡献、风险等级分布、待办队列、系统健康 | 无；指标跳转到带筛选条件的列表。 |
| 告警中心 | 分页检索、告警详情、可信证据、关联事件、分派历史、处置时间线 | 分派、确认、开始调查、关闭、标记误报。 |
| 事件审计 | 安全事件检索、动作/主体/资源/结果、可信事实、关联规则和告警 | 无。 |
| 控制中心 | 控制记录、执行详情、TTL、审批队列、执行尝试 | 批准、驳回、失败重试、手工会话吊销。 |
| 检测策略 | 规则目录、风险级别、模式、阈值、版本和生效提示 | 经独立审批人的版本化规则变更。 |
| 白名单 | 预置范围、状态、有效期和版本 | 授权、撤销。 |
| 管理审计 | 操作者、操作、资源、结果、时间和请求标识的只读检索 | 无。 |

所有列表提供关键字、领域筛选、排序、分页、加载态、空态和失败重试。风险态势使用 ECharts；其余页面以高密度表格为主。

## 核心交互

### 告警处置

告警中心采用“查询表格 + 详情抽屉”。打开详情不改变当前查询、排序和分页。抽屉包含风险证据、处置时间线、分派历史和关联事件标签页。

处置命令携带 `expectedVersion`。分派、关闭、误报等操作必须填写合规原因；写操作成功后重新读取详情和当前列表。若服务端返回 `409`，前端保留用户输入、读取最新版本、展示可理解的变化并允许重新提交，绝不静默覆盖。

### 控制审批

待审批控制优先展示。详情包含动作类型、目标主体、来源告警、规则、TTL、当前状态、执行次数和安全的失败原因。批准、驳回、失败重试和手工会话吊销均通过确认表单展示影响范围；失败重试必须使用幂等命令。

### 规则治理

规则列表展示当前持久化版本、模式、阈值和风险级别。变更必须填写原因和幂等键，由服务端独立上下文解析第二审批人。前端明确提示：新持久化版本不会替换已经冻结的运行时规则，仍需受控发布或重启生效。

### 白名单

页面只显示服务端预置条目。授权和撤销携带期望版本与原因，冲突处理与告警一致。页面不提供新增、复制或编辑作用域入口。

## 视觉系统

- 主导航使用深青 `#153A45`，激活态使用中青 `#2A6266`，品牌或审批强调使用琥珀 `#EFBA50`。
- 工作区使用冷白和浅灰绿背景，避免米色、单一蓝色或整页深色。
- 高风险使用克制的红色，审批和待确认使用琥珀色，正常和成功使用青绿色。
- 页面保持银行后台所需的信息密度；指标卡只用于真实指标，不把每个区块包装成浮动卡片。
- 字号不随视口宽度缩放；表格、工具栏、按钮和状态标签使用稳定尺寸。
- 桌面优先支持 1440px 和 1280px；窄屏下表格允许受控横向滚动，详情抽屉使用视口约束，不发生文本或操作按钮重叠。
- 高风险不只依赖颜色表达，必须同时显示文字等级或图标。

## Mock 模式

Mock 数据必须确定、可复位，并覆盖：

- 多风险等级、全部告警状态、已分派和未分派队列。
- 告警分派、确认、调查、关闭和误报完整状态转换。
- 控制等待审批、成功、失败、驳回及失败重试。
- 规则模式和阈值的双人复核变更。
- 白名单授权和撤销。
- 空数据、加载失败、权限拒绝、版本冲突、非法状态转换和未知错误。

Mock Repository 在内存中执行与服务端一致的分页、筛选、版本递增和状态校验。提供开发态场景切换与重置能力，但不在生产构建中显示调试控件。

## HTTP 与响应契约

HTTP Repository 统一使用 Jeecg 风格的 Axios `defHttp`，不得在业务代码中使用原生 `fetch` 或裸 Axios。

成功响应：

```json
{
  "success": true,
  "code": 200,
  "message": "操作成功",
  "result": {},
  "timestamp": 1785367200000
}
```

失败响应保留正确 HTTP 状态并使用同构包装：

```json
{
  "success": false,
  "code": 409,
  "message": "数据已被其他操作员更新",
  "result": {
    "errorType": "CONFLICT",
    "errorCode": "MON-202",
    "requestId": "req-example",
    "details": {}
  },
  "timestamp": 1785367200000
}
```

`defHttp` 负责 Token、响应解包、取消请求、HTTP 状态和通用消息策略。HTTP Repository 负责将响应映射为领域模型并解释领域错误。

Spring 宿主需补齐：

- 事件分页和详情。
- 告警分页、详情、分派历史、误报处置和现有全部状态命令。
- 控制分页、详情、批准、驳回和失败重试。
- 规则分页和详情。
- 白名单分页和详情。
- 管理审计分页查询。
- 风险态势所需的聚合端点，或由现有分页查询在验收数据规模下组合生成。

Controller 只做 HTTP DTO 映射。操作者和系统范围继续由服务端上下文派生；授权、版本校验、状态转换、持久化和管理审计由现有管理 Service 完成。

## 错误模型

前端内置但不限于以下错误语义：认证失效、权限拒绝、资源不存在、输入校验失败、版本冲突、非法状态转换、限流、服务不可用、网络异常和请求取消。

错误类型采用开放字符串而非封闭枚举。未知后端类型归入展示类别 `UNKNOWN`，同时保留原始 `errorType`、稳定 `errorCode`、HTTP 状态、`requestId` 和安全详情，便于以后追加类型而不破坏前端。

- `401/403` 使用明确状态页面或结果提示，不能只靠隐藏按钮。
- `409` 执行重新读取和冲突恢复。
- 状态机写操作等待服务端确认，不使用误导性的乐观 UI。
- 列表切换和抽屉切换取消过期请求，取消不显示为业务失败。
- 错误、日志和通知禁止显示密码、Token、Cookie、请求头、原始载荷、SQL 或异常原因链。

## 测试与验收

### 前端自动化

- Vitest 覆盖 Repository 契约、分页转换、字典映射、状态操作可用性、错误归一化和脱敏。
- 组件测试覆盖 `BasicTable` 查询/分页、`BasicForm` 校验、Modal/Drawer 生命周期和冲突恢复。
- Mock 流程测试覆盖全部告警、控制、规则和白名单写操作，以及失败分支。
- TypeScript 类型检查和 Vite 生产构建必须通过。

### 视觉验收

使用 Playwright 在桌面和移动视口检查风险态势、列表、抽屉、表单、弹窗、空态和错误态。验收截图需确认无重叠、截断、布局跳动、空白图表或不可达操作；交互验证至少包含分页、筛选、抽屉切换和确认表单。

### 联调和后端回归

- 为 Spring 3 新增 Controller 响应包装、分页、权限拒绝、冲突和写操作契约测试。
- Spring 2 使用对等契约测试保证路径和响应兼容。
- 运行 Spring 3 宿主后执行真实 API 冒烟流程，验证管理审计留痕和服务端派生身份。
- 运行相关 Maven 模块测试；完成实现后运行 `mvn clean verify -DskipTests=false`。

## 完成标准

- `npm run dev` 默认进入 Mock 模式并可操作所有页面。
- `VITE_DATA_MODE=http` 可连接 Spring 3 宿主，无页面代码分支。
- 表单、表格、分页、弹窗和抽屉统一通过 Jeecg 兼容组件层使用。
- HTTP 调用统一通过 `defHttp`，后端统一返回 Jeecg `Result<T>`。
- Mock 和 HTTP Repository 满足同一契约。
- 页面覆盖成功、空、加载、拒绝、冲突、非法转换和未知错误状态。
- 前端测试、类型检查、构建、Playwright 视觉验收和相关 Maven 测试通过。

## 明确不做

- 不把集成审计宿主改造成生产 JeecgBoot 脚手架。
- 不复制完整 JeecgBoot 权限、租户、菜单生成或代码生成体系。
- 不允许前端提供可信身份、系统范围或组织范围。
- 不提供白名单任意新增、规则在线热替换或未经审批的 ENFORCE 变更。
- 不在第一阶段实现真实通知渠道、生产级身份登录或生产部署配置。
